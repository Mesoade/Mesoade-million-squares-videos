# The Million Squares: video house style

This repo holds the short-form videos for The Million Squares (one square per
person, $10, forever). Every video is a Remotion composition built over a
talking-head clip.

This file is a style memory, not a template. It records what worked in the
videos so far, so new videos feel like the same channel. Each video still
gets its own edit. Treat everything under **Defaults** as the starting point,
and change it when the footage or the message calls for it. **Constants** are
the few things that keep the brand recognizable.

Reference edit: `src/videos/day6/` (Day 6 update, 70s, 11 cutaways). The
owner liked it, so match its quality, not its exact sequence.

---

## Constants (keep these unless the owner asks otherwise)

- **Never cover the speaker's face or the burned-in captions.** The owner
  asked for this directly. B-roll lives in the space the face and captions
  don't use. Measure that space for every clip (see Workflow), because
  framing changes between recordings.
- **Audio = the original voice + sound effects only.** No music unless asked.
  SFX sit well under the voice (0.13–0.5 volume, voice peaks around −10 dB).
- **Brand look:** warm near-black panels, cream text, one orange accent.
  Serif headlines (Playfair Display, italic orange for the key word), Inter for
  labels, numbers and UI. The square is the visual motif.
- **Honest numbers.** Show the real figures (claimed count, day, price). If a
  visual can't be to scale, say so on screen (Day 6 did this:
  "not to scale").
- **Don't invent content.** Use real site imagery, and use placeholder bars
  instead of made-up user stories or quotes.
- **Captions are already burned into the source.** Don't add a second caption
  track unless the owner sends a clip without them.

## Defaults (change these freely)

### Layout
- **Top B-roll panel** (`Panel`) from y=0 down to the video's `panelH`, set
  per video in its `LayoutProvider` (Day 6: 830px, because the head starts at
  ~870px and the captions at ~1300px).
- Inside the panel: small tracked uppercase **label** at ~y=58 (the "chapter",
  e.g. THE MATH SO FAR, THE PLAN), then a serif **title** at ~y=100, about
  80px, then one visual. One idea per panel.
- Alternatives when the footage calls for it: full-bleed B-roll (no captions,
  or the face is not needed), side or corner picture-in-picture, a lower band
  if the face sits high, or no panel at all (just an overlay sticker or number
  pop next to the face). Choose by measuring the footage, not by habit.

### Motion
- Panel wipes down in 9 frames and up in 8 (`EASE_IN_OUT`), with a 6px orange
  edge riding the wipe. Back-to-back panels hard-cut: the first one takes
  `noExit`, the next one `noEnter`. The end card takes `noExit`.
- Elements ease in with `EASE_OUT` over 10–14 frames, rising about 40px.
  Grids stagger 0.5–1.5 frames per item.
- Emphasis comes from scale settling, e.g. 1.2→1, or 2.2→1 for a single
  square lighting up, plus an orange glow. Stamps land 1.8→1 with a thud.
- Numbers count or tick up instead of appearing all at once.

### Pacing
- Cut to B-roll on the keyword the visual illustrates. The panel should be up
  when the word lands, which usually means starting it 0.2–0.5s before.
- Cutaways run about 2–6s. Over the video, roughly half of the runtime is
  plain speaker. Keep the speaker on screen for emotional or personal lines (Day 6:
  "this is quite humbling", "it reminds us of our humanity").
- Open with a cutaway in the first second, so a number or visual hooks the
  viewer. Close on the end card over the call to action.

### Sound (`src/shared/Sfx.tsx`, generated by `scripts/make-sfx.sh`)
| Effect | Use | Default volume |
|---|---|---|
| whoosh | every panel entry (built into `Panel`), flying elements | 0.18 |
| tick | counters and calendar checks, one per step | 0.22 |
| pop | an item appearing or landing (lower to about 0.13–0.18 in bursts) | 0.28 |
| ding | the payoff number or reveal, about once per scene | 0.2 |
| thud | stamps, hard statements | 0.5 |
| riser | build-up to a spike ("goes viral") | 0.28 |
| click | cursor clicks on UI | 0.45 |

The network here usually can't download SFX, so add new effects to the
script, synthesized with ffmpeg.

## Scene library (in `src/videos/day6/scenes.tsx`; copy and adapt)

Pick the scene by what the line *means*, not by the literal words.

| Talking point type | Day 6 scene | Idea |
|---|---|---|
| Day number or progress | `DayCounter` | number ticks up, row of squares fills |
| Proof from the product | `SiteScreenshot` | real screenshot, zoom to the stat, orange ring |
| Big-number math | `MillionMath` | grid of squares, a few light up, then a ratio, a % chip and a punchline |
| A commitment or schedule | `ThirtyDays` | calendar with done days checked and today outlined |
| Growth through sharing | `Virality` | one node spreading into rings |
| A hard "zero" or "no" | stamp in `Virality` | rotated orange stamp with a thud |
| Many attempts, one hit | `OneGoesViral` | row of cards, one lifts and glows, curve spikes |
| Personal growth | `ComfortZone` | square leaves a dashed circle |
| The ask or user action | `FavoritePhoto` | photo flies into an empty slot on the wall |
| Global reach | `World` | wireframe globe with pulsing square pins |
| How the product works | `ClickStory` | cursor clicks a tile, card expands |
| Call to action | `EndCard` | mark, wordmark, headline, CTA pill, live claimed count |

More scenes in `src/videos/math-vs-reality/scenes.tsx` (funnel math and plan vs. reality):

| Talking point type | Scene | Idea |
|---|---|---|
| A plan or pipeline | `ThePlan` | big number counts up, three step cards with arrows, last one glows |
| A percentage assumption | `OnePercent` | big % counts up, label, verdict chip |
| "1 in N" | `HundredViewers` | 10×10 grid, one square lights up, the rest dim, title swaps |
| Step-by-step arithmetic | `TheMath` / `Payoff` | stacked rows, the result ticks up, a progress bar fills to "all filled" |
| Plan vs. reality | `MathVsLife` / `RealityCheck` | dashed plan line vs. flat orange line; plan bar vs. a to-scale sliver |
| Two options | `TwoLevers` | two cards with an "or" badge |
| Batches over time | `Batches` | week columns filling in turn, the next one dashed and pulsing |
| Variety and diversity | `Mosaic` | wall of color-grouped squares with real photo tiles |

`FavoritePhoto` takes `label`/`title`, and `EndCard` takes `claimed` (`null` hides
the count when no fresh figure is available).

Invent new scenes whenever none of these fits. Keep them inside the brand
tokens and motion defaults. When a new scene works well, move it to
`src/shared/` and add it to this table.

## Workflow

1. **Put the clip in place:** `public/<video>/source.mp4`. It's git-ignored
   because of its size. Probe it with
   `ffprobe` for duration, fps and resolution (so far: 1080×1920, 30fps).
2. **Transcribe from the burned-in captions:** run
   `scripts/contact-sheet.sh public/<video>/source.mp4 <scratch>/sheets`, then
   read the sheets. You get the words with timestamps to ~0.5s (use fps=4
   for tight cuts). Whisper models usually can't be downloaded here.
3. **Measure the footage:** grab a full-res frame
   (`ffmpeg -ss 5 -i clip -frames:v 1 f.png`) and note the head top and the
   caption band. Check the sheets for movement across the whole clip, then
   set `panelH` (or pick another layout) from those numbers.
4. **Plan the beat sheet:** list `time → line → scene`, and decide where the
   speaker stays on screen.
5. **Build:** create `src/videos/<video>/` with its own composition and
   scenes, importing from `src/shared/`. Register it in `src/Root.tsx`. Keep
   `Sequence` `from`/`durationInFrames` hard-coded frame numbers with
   descriptive `name`s.
6. **Check stills before rendering the full video.** Render one still per
   scene, tile them, and look at them, mainly to confirm the face and captions
   stay clear:
   `npx remotion still <Id> out/s.jpg --frame=N --scale=0.5 --browser-executable=<chrome>`
7. **Render:** `npx remotion render <Id> out/<video>.mp4 --crf=18`. In the
   cloud sandbox, add
   `--browser-executable=/opt/pw-browsers/chromium_headless_shell-1243/chrome-headless-shell-linux64/chrome-headless-shell`
   (don't commit that path). Then send the file to the owner.

## Repo notes

- This repo is deliberately **separate from the website repo** (`Mesoade/Mesoade`,
  which deploys to Vercel). Never add video work there.
- `src/shared/`: theme, `Panel`, `Sfx`, layout context, UI helpers
  (`useProgress`, `mix`, `Title`, `Em`, `BrandMark`, `photo`).
- `src/videos/<video>/`: one folder per video.
- `public/fonts`, `public/sfx`, `public/brand` are shared;
  `public/<video>/` holds that video's own assets.
